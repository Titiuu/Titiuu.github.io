# Blog Draft

使用这个技能帮助用户把主题、想法、资料或已有草稿整理成一篇中文博客文章。默认输出面向博客发布，强调结构清晰、论证有据、语气一致，并保留可迭代的提纲和草稿版本。

## 输入判断

先判断用户是在创建新文章，还是更新已有文章：

- **新文章**：用户提供主题、想法、资料链接、文件、目标读者、语气或字数需求。
- **已有文章迭代**：用户提供现有草稿路径、文章内容，或明确要求修改、扩写、压缩、润色已有文章。

如果是已有文章迭代，先阅读现有草稿和相关上下文，直接进入“迭代修改”流程，不重新创建研究目录或提纲，除非用户明确要求。

## 新文章流程

### 1. 建立文章工作目录

使用 `YYYY-MM-DD-short-topic-name` 作为目录名：

- 日期使用当前日期。
- slug 用主题生成，保持小写、连字符连接，最多 5 个词。
- 默认目录为 `blog-posts/YYYY-MM-DD-short-topic-name/`，除非项目已有明显的博客目录约定。

目录结构：

```text
blog-posts/
└── YYYY-MM-DD-short-topic-name/
    └── resources/
```

如果项目已有更具体的博客分类目录，例如 `blogs/tech/`、`blogs/projects/`，优先遵循项目既有结构。

### 2. 研究与资源整理

对用户提供的资料进行整理：

- URL：获取关键信息，保存摘要到 `resources/`。
- 文件：阅读后提炼摘要，保存到 `resources/`。
- 只有主题没有资料：根据需要使用网络搜索收集最新信息；涉及近期事实、产品、数据、法规或趋势时必须核验。

每个资源摘要使用：

```text
resources/source-N-short-name.md
```

摘要格式：

```markdown
# 来源：[标题/URL]

## 要点
- 要点 1
- 要点 2

## 相关引文/数据
- 引文或统计 1
- 引文或统计 2

## 与主题的关联
简要说明其相关性
```

### 3. 澄清写作方向

在提纲前确认会显著影响文章的事项：

- 核心结论：读者最终应该记住什么。
- 目标读者：技术、通用、商业、学习笔记等。
- 目标长度：短篇 500-800 字，中篇 1000-1500 字，长篇 2000+ 字。
- 语气：正式、轻松、技术向、对话式等。
- 排除内容：用户不希望出现的角度或材料。

如果用户已提供足够信息，直接根据合理默认继续，不为低影响细节打断流程。

### 4. 生成并保存提纲

读取 `assets/outline-template.md`，按模板生成结构化提纲。提纲应包含：

- 目标读者、语气、目标长度、核心结论。
- 开场钩子、背景、论点。
- 各部分标题、关键点、证据来源和段落衔接。
- 结论和需要引用的来源。

保存为文章目录中的 `OUTLINE.md`。如果用户要求先确认提纲，先展示提纲并等待反馈。

### 5. 撰写草稿

读取 `assets/draft-template.md`，基于已批准或已确定的提纲撰写完整草稿。草稿要求：

- 严格围绕 `OUTLINE.md` 的结构展开。
- 引言有清晰钩子，正文有自然过渡，结尾回到核心结论。
- 所有统计数据、比较、市场趋势、研究发现、基准测试和事实性断言都需要引用来源。
- 使用行内引用，例如 `[1]`、`[Source Name]` 或 `[Author, Year]`。
- 文末包含“参考资料”。

成稿后使用 `natural-chinese-writing` 做一次自然表达检查。默认保留篇幅、章节和有用格式，重点修改机械的“不是……而是……”句式、无信息增益的列举和没有依据的拔高表达。

初稿保存为：

```text
draft-v0.1.md
```

后续版本递增为 `draft-v0.2.md`、`draft-v0.3.md` 等，保留历史版本。

## 已有文章迭代

编辑已有文章时：

1. 阅读现有草稿、提纲和相关资源。
2. 根据用户反馈判断修改类型：结构调整、扩写、压缩、润色、事实核验、语气调整、格式整理或降低 AI 痕迹。涉及自然表达或模板化问题时，使用 `natural-chinese-writing` 的诊断与改写流程。
3. 尽量保留原文章意图和已有风格。
4. 涉及事实更新或新增事实性论断时，补充或更新引用。
5. 保存为新版本，除非用户明确要求覆盖原文件。

## Git 行为

不要默认提交或推送。只有用户明确要求时，才执行 git 暂存、提交或推送。

推荐提交信息：

- 提纲：`docs: add outline for blog post - [topic-name]`
- 草稿：`docs: add draft v0.1 for blog post - [topic-name]`
- 迭代：`docs: update blog draft - [topic-name]`

## 质量标准

- 文章开头应快速建立读者问题或主题张力。
- 每一节只承担一个清晰任务，避免散点堆砌。
- 段落之间需要有自然承接。
- 技术文章优先准确、可验证、可复现。
- 观点文章需要区分事实、推断和个人判断。
- 短段落优先，必要时使用列表提高可读性。
- 经验口吻应有真实依据，结论不能越过文中事实和论证。
- 结尾应停在论证能够支撑的位置；只有内容确实需要时，才总结核心收获或提出后续问题。
