# C++ 语言面试笔记

这篇笔记是我24年初的时候准备面试的时候写的第一篇笔记，也是我整理我的博客内容的第一篇。内容按面试中最常被追问的路径整理：内存与对象表示、资源管理、面向对象、现代 C++ 和 STL。它不是语法大全，更像是一份复习地图：先给能直接回答面试官的问题，再补充容易说错的边界。

## 一、内存与对象表示

### struct 和 union 的区别

`struct` 和 `union` 都可以把不同类型的数据组织在一起，但它们的内存模型不同。

`struct` 中每个非静态数据成员都有自己的存储位置，成员按声明顺序排列，中间可能插入 padding 用于对齐。因此 `sizeof(struct)` 通常不是所有成员 `sizeof` 的简单相加，而是“成员大小 + 对齐填充”之后的结果。

```cpp
struct S {
    char c;   // 1 byte
    int i;    // 通常需要 4 字节对齐
};

// 在常见 ABI 下 sizeof(S) 通常是 8，而不是 5。
```

`union` 的所有非静态成员共享同一段存储空间。一个 `union` 对象的大小至少能容纳最大成员，并满足最严格成员的对齐要求。任一时刻通常只有一个“活跃成员”，这也是面试里常见的追问点：`union` 省空间，但要小心对象生命周期和类型访问规则。

```cpp
union U {
    int i;
    double d;
};

// sizeof(U) 通常等于能容纳 double 的大小，并满足 double 的对齐要求。
```

一句话回答：`struct` 是“并列存储”，`union` 是“共享存储”；`struct` 更适合表达一个对象的多个属性，`union` 更适合表达“多选一”的存储。

### struct 内存对齐

内存对齐的核心原因是 CPU 访问效率和硬件约束。很多处理器访问对齐地址上的数据更快；如果一个 `double` 跨越了机器字或缓存访问边界，CPU 可能需要多次读取再拼接，效率下降，某些架构甚至会触发异常。

对齐规则不能简单写成“x86 是 4 字节，x64 是 8 字节”。更准确的说法是：每种类型都有自己的 alignment requirement，可以用 `alignof(T)` 查看；结构体成员会按成员类型的对齐要求放置，整个结构体的大小还要补齐到其最大对齐要求的整数倍。实际结果受平台 ABI、编译器和 `#pragma pack`、`alignas` 等设置影响。

常见规则可以这样记：

- 成员地址要满足该成员类型的对齐要求。
- 结构体整体对齐要求通常是所有成员对齐要求的最大值。
- 结构体大小通常要补齐到整体对齐要求的整数倍。
- 调整成员声明顺序可能减少 padding，但不要为了省几个字节牺牲可读性，除非这是明确的性能或内存热点。

### C++ 进程内存布局

经典面试图通常把进程虚拟地址空间分成几段：

```text
高地址
栈 stack
堆 heap
BSS 段
Data 段
Text/Code 段
低地址
```

这个图适合用来理解变量生命周期，但它不是所有系统的精确布局。真实布局还会受操作系统、链接器、动态库、ASLR、线程栈和内存映射区影响。

常见区域含义：

- `stack`：函数调用栈，存放局部自动变量、返回地址、部分调用现场等，自动分配和释放。
- `heap`：动态分配区域，`new`、`malloc` 等通常从这里申请空间，需要手动释放或交给 RAII 对象管理。
- `BSS`：未显式初始化或初始化为零的全局变量、静态变量。
- `Data`：已初始化的全局变量、静态变量。
- `Text/Code`：程序机器指令，通常只读。

### static 和 const

`static` 的含义取决于出现位置。

局部静态变量：

```cpp
void f() {
    static int count = 0;
    ++count;
}
```

`count` 生命周期贯穿整个程序，但作用域只在函数内部。它只初始化一次，常见实现会放在静态存储区。

文件作用域的静态变量或函数：

```cpp
static int file_only_value = 1;
static void helper() {}
```

它们具有内部链接，只能在当前翻译单元访问。面试中可以说它限制了符号可见性，减少命名冲突。

类中的静态成员：

```cpp
class A {
public:
    static int count;
    static void print_count();
};
```

静态成员变量属于类，不属于某个对象，所有对象共享一份。传统写法需要在类外定义；C++17 起可以用 `inline static` 在类内定义。静态成员函数没有 `this` 指针，因此不能直接访问非静态成员，也不能声明为 `const` 成员函数，因为成员函数末尾的 `const` 修饰的是隐式的 `this`。

`const` 表示对象或接口的只读约束：

- 修饰变量：变量初始化后不能通过该名字修改。
- 修饰形参或返回值：限制函数内部或调用方修改。
- 修饰成员函数：承诺不修改对象的可观察状态。

`const` 比 `#define` 更适合定义常量。`#define` 是预处理替换，没有类型、作用域和调试信息；`const` 有类型检查，也遵守 C++ 的作用域规则。现代 C++ 中，编译期常量还常用 `constexpr`。

### new/delete 和 malloc/free

`malloc/free` 是 C 标准库函数，`new/delete` 是 C++ 运算符。

主要区别：

- `malloc` 需要显式给出字节数，返回 `void*`；`new` 根据类型计算大小，返回正确类型的指针。
- `malloc` 只分配原始内存，不调用构造函数；`new` 会分配内存并调用构造函数。
- `free` 只释放内存，不调用析构函数；`delete` 会先调用析构函数，再释放内存。
- `new` 分配失败默认抛出 `std::bad_alloc`；`malloc` 失败返回 `nullptr`。

为什么有了 `malloc` 还要有 `new`？因为 C++ 对象不仅是一块内存，还涉及构造、析构和类型系统。`new/delete` 把对象生命周期纳入语言规则，适合管理 C++ 对象。

`free` 怎么知道释放多少？常见内存分配器会在返回给用户的地址附近保存元数据，例如分配块大小。但这是实现细节，不是 C++ 语言保证。程序员只需要保证传给 `free` 的指针来自匹配的分配函数，并且只释放一次。

## 二、值类别与资源管理

### 左值和右值

简单回答：左值通常有身份，可以取地址，可以出现在赋值号左侧；右值通常表示临时值或即将被消耗的值。

```cpp
int x = 1;   // x 是左值
int y = x + 2; // x + 2 是右值
```

现代 C++ 更精细地区分 lvalue、prvalue、xvalue，但面试中先讲清“有没有稳定身份、能否被移动”通常就够了。

### 移动语义和 std::move

移动语义的目标是减少不必要的深拷贝。对于持有资源的对象，例如 `std::vector`、`std::string` 或自己管理堆内存的类，移动构造可以把资源所有权从旧对象转给新对象，而不是重新分配并复制全部数据。

关键点：`std::move` 本身不移动任何东西，它只是把表达式转换成右值引用，让后续重载解析有机会选择移动构造或移动赋值。

```cpp
std::string a = "hello";
std::string b = std::move(a); // 真正的资源转移发生在 string 的移动构造中
```

被移动后的对象仍然有效，但值处于未指定状态。可以析构、重新赋值，不应该依赖它原来的内容。

### 完美转发和 std::forward

`std::forward` 用在模板转发场景，目标是保留实参原本的值类别：传进来是左值，就继续作为左值传递；传进来是右值，就继续作为右值传递。

```cpp
template <typename T>
void wrapper(T&& arg) {
    target(std::forward<T>(arg));
}
```

面试中可以这样区分：

- `std::move`：无条件把表达式转成右值。
- `std::forward`：有条件转发，依赖模板参数 `T` 保留左值/右值特征。

### 深拷贝和浅拷贝

浅拷贝只复制成员本身。如果成员里有裸指针，浅拷贝会让两个对象指向同一块资源，可能导致悬空指针、重复释放或意外共享修改。

深拷贝会重新申请资源，并复制资源内容，使两个对象拥有独立资源。

```cpp
class Buffer {
public:
    Buffer(const Buffer& other)
        : size_(other.size_), data_(new char[other.size_]) {
        std::copy(other.data_, other.data_ + size_, data_);
    }

    ~Buffer() {
        delete[] data_;
    }

private:
    std::size_t size_;
    char* data_;
};
```

现代 C++ 更推荐 RAII：能用 `std::vector`、`std::string`、`std::unique_ptr` 等标准类型管理资源，就不要手写 `new/delete`。这也对应“Rule of Zero”：如果成员自己会正确管理资源，类通常不需要自定义析构、拷贝和移动函数。

## 三、面向对象相关

### C++ 多态有哪些

常见可以分三类：

- 函数重载、运算符重载：编译期多态。
- 模板、函数模板、类模板：编译期多态。
- 虚函数：运行期多态，通过基类指针或引用调用派生类实现。

### 构造函数有哪些

常见构造相关函数：

- 默认构造函数：无参或所有参数都有默认值。
- 普通构造函数：按参数初始化对象。
- 拷贝构造函数：`T(const T&)`。
- 移动构造函数：`T(T&&)`。
- 拷贝赋值和移动赋值虽然不是构造函数，但常和它们一起讨论。

拷贝构造为什么要用引用传递？如果按值传递参数，需要先拷贝实参生成形参，而拷贝形参又会调用拷贝构造，导致无限递归。

```cpp
class A {
public:
    A(const A& other); // 正确
    // A(A other);     // 错误思路：会递归调用拷贝构造
};
```

构造函数可以抛异常。析构函数不建议抛异常，尤其是在栈展开期间再次抛异常会导致 `std::terminate`。因此析构函数应尽量 `noexcept`，把可能失败的清理操作放到显式接口中处理。

### 构造和析构顺序

构造派生类对象时：

1. 先构造基类子对象。
2. 再按成员声明顺序构造成员对象。
3. 最后执行派生类构造函数体。

析构顺序相反：

1. 先执行派生类析构函数体。
2. 再析构成员对象。
3. 最后析构基类子对象。

静态存储期对象在 `main` 之前或首次使用时初始化，析构通常发生在程序结束阶段。不同翻译单元之间的初始化顺序要谨慎，这就是常说的 static initialization order 问题。

### this 指针

`this` 是非静态成员函数中的隐式指针，指向当前调用该成员函数的对象。

```cpp
class A {
public:
    void set(int value) {
        this->value = value;
    }

private:
    int value = 0;
};
```

静态成员函数没有 `this` 指针，所以不能直接访问普通成员变量。

在成员函数中 `delete this` 只有在对象确实由 `new` 创建，并且删除后不再访问任何成员时才可能成立，但这是一种非常危险的设计。析构函数中调用 `delete this` 会递归触发析构，通常导致栈溢出或未定义行为。

### inline 函数

`inline` 最初用于建议编译器在调用点展开函数体，减少函数调用开销。现在更重要的语义是允许函数或变量在多个翻译单元中有重复定义，只要定义完全一致，链接时满足 ODR 要求。

和宏相比，`inline` 函数有类型检查、作用域和调试信息，更符合 C++ 语言规则。

### 友元函数

友元函数或友元类可以访问类的 `private` 和 `protected` 成员。

```cpp
class A {
    friend void print(const A& a);
private:
    int value = 0;
};
```

友元会破坏封装边界，因此应谨慎使用。常见合理场景包括运算符重载、序列化、测试辅助或两个类之间确实存在紧密协作。

### 虚函数、虚函数表和虚函数指针

包含虚函数的类通常会有一张虚函数表，表中保存虚函数入口地址；每个对象通常有一个虚函数指针，指向所属动态类型对应的虚函数表。调用虚函数时，通过对象的虚函数指针找到表，再调用实际函数。

需要注意：虚函数表和虚函数指针是常见实现模型，不是 C++ 标准强制规定的具体布局。但主流编译器基本都采用类似机制。

虚函数表是类级别共享的，对象里通常只保存虚函数指针。因此不是“每个对象一张虚函数表”，而是“每个对象一个指向虚表的指针”。

如果派生类很多但不重写某个虚函数，不会为每个对象复制函数代码。空间开销主要来自每个多态对象中的虚指针，以及每个类对应的虚表。

### 构造函数能是虚函数吗

构造函数不能是虚函数。对象在构造期间还没有成为完整的派生类对象，虚派发机制不能用于“决定构造哪个类型”。构造哪个类必须在编译期和对象创建表达式中确定。

构造和析构期间调用虚函数也要谨慎。在基类构造函数中调用虚函数，不会派发到派生类重写版本，因为派生类部分还没构造完成；析构阶段同理。

### 析构函数为什么常设为 virtual

如果一个类要作为基类，并且可能通过基类指针删除派生类对象，基类析构函数必须是虚函数。

```cpp
class Base {
public:
    virtual ~Base() = default;
};
```

否则：

```cpp
Base* p = new Derived();
delete p; // 如果 Base 析构非 virtual，行为未定义
```

如果类不打算被继承，可以标记为 `final`，或让析构函数非虚；如果类作为接口基类，通常使用虚析构。

### 纯虚函数和抽象类

纯虚函数用 `= 0` 声明：

```cpp
class Shape {
public:
    virtual double area() const = 0;
    virtual ~Shape() = default;
};
```

含有纯虚函数的类是抽象类，不能直接实例化。它适合表达接口，让派生类提供具体实现。

### explicit

`explicit` 用来阻止构造函数或转换函数参与隐式类型转换。

```cpp
class String {
public:
    explicit String(const char* s);
};
```

面试回答可以很短：单参数构造函数容易引入意外隐式转换，`explicit` 可以让转换必须显式写出来，提高代码可读性和安全性。

## 四、C++11 与现代特性

### auto 和 decltype

`auto` 根据初始化表达式推导变量类型：

```cpp
auto x = 1;        // int
auto it = v.begin();
```

`decltype(expr)` 获取表达式的类型，不一定需要真正执行表达式，常用于模板、返回类型推导和保留引用/const 属性。

为什么有了 `auto` 还要有 `decltype`？因为 `auto` 解决的是“变量声明时从初始化器推导类型”，`decltype` 解决的是“查询某个表达式的精确类型”。两者用途不同。

### 智能指针

智能指针的核心是 RAII：对象生命周期结束时自动释放资源。

`std::unique_ptr` 表示独占所有权，不能复制，但可以移动。默认优先使用它，因为所有权最清晰，开销也低。

```cpp
auto p = std::make_unique<int>(42);
auto q = std::move(p); // 所有权转移
```

`std::shared_ptr` 表示共享所有权，通过控制块维护引用计数。最后一个 `shared_ptr` 销毁时释放对象。它适合确实存在共享生命周期的场景，但不要因为“不知道谁负责释放”就滥用。

`std::weak_ptr` 不增加引用计数，用来观察由 `shared_ptr` 管理的对象。它常用于打破循环引用。

```cpp
if (auto locked = weak.lock()) {
    // 对象仍然存在
}
```

`std::auto_ptr` 是旧标准中的智能指针，C++11 起弃用，C++17 已移除。它的复制会转移所有权，语义危险，现代 C++ 不应再使用。

关于线程安全要说准确：多个 `shared_ptr` 实例共享同一个控制块时，引用计数增减通常是线程安全的；但通过它们访问被管理对象，对象本身并不会自动变成线程安全。

### lambda 表达式

lambda 本质上会生成一个匿名函数对象。捕获列表对应这个函数对象的成员，参数列表对应 `operator()` 的参数。

```cpp
int base = 10;
auto add = [base](int x) {
    return base + x;
};
```

可以这样理解：

- 捕获列表：决定闭包对象保存哪些外部变量。
- 参数列表：决定调用时传入什么。
- 函数体：对应重载的函数调用运算符。

### volatile

`volatile` 告诉编译器，对该对象的读写具有可观察副作用，不能随意优化掉，也不能简单缓存到寄存器中。它常用于内存映射 I/O、信号处理等特殊场景。

不要把 `volatile` 当作多线程同步工具。线程间同步应该使用 `std::atomic`、互斥锁、条件变量等并发原语。

## 五、STL 容器与常见追问

### 顺序容器

`vector`：底层是连续数组，支持快速随机访问，尾部插入均摊 O(1)。扩容时会重新分配更大的连续空间，并移动或拷贝原有元素，因此可能导致指针、引用和迭代器失效。

`array`：固定大小数组，大小是类型的一部分，支持随机访问，不能动态增删。

`list`：双向链表，任意位置插入删除稳定，但不支持随机访问，缓存局部性较差。

`forward_list`：单向链表，只支持单向遍历，比 `list` 更省空间。

`deque`：分段连续存储，通常由中央控制结构管理多个缓冲区。支持随机访问，也支持头尾快速插入删除；中间插入删除仍然较慢。

### 容器适配器

`stack`、`queue`、`priority_queue` 是容器适配器，不是独立的基础容器。

- `stack` 默认常以 `deque` 为底层容器，只暴露栈顶操作。
- `queue` 默认常以 `deque` 为底层容器，只暴露队头和队尾操作。
- `priority_queue` 默认以 `vector` 为底层容器，并用堆算法维护优先级。

`stack` 和 `queue` 不默认用 `vector` 的核心原因不是“容量有限制”，而是接口需求不完全匹配。比如 `queue` 需要高效从头部弹出，`vector` 的头部删除是 O(n)。

### 关联容器和无序容器

有序关联容器通常基于平衡二叉搜索树实现，主流实现多为红黑树：

- `set`：有序、键唯一。
- `multiset`：有序、键可重复。
- `map`：有序、键唯一，保存 key-value。
- `multimap`：有序、键可重复，保存 key-value。

无序关联容器通常基于哈希表实现：

- `unordered_set`：无序、键唯一。
- `unordered_multiset`：无序、键可重复。
- `unordered_map`：无序、键唯一，保存 key-value。
- `unordered_multimap`：无序、键可重复，保存 key-value。

面试回答复杂度时要注意：

- 有序关联容器查找、插入、删除通常是 O(log n)。
- 无序关联容器平均 O(1)，最坏 O(n)，受哈希函数、负载因子和冲突情况影响。

### vector 扩容

`vector` 要保证元素连续存储，因此容量不足时会申请一块更大的连续内存，把旧元素移动或拷贝过去，再释放旧空间。

扩容倍率不是 C++ 标准规定的。不同标准库实现可以选择 1.5 倍、2 倍或其他策略。面试时不要说死“vector 一定扩容 1.5 倍”，更准确的说法是：标准只要求满足复杂度等语义约束，具体增长策略由实现决定。

常见追问：

- 扩容后原来的迭代器、引用、指针会失效。
- `reserve(n)` 可以提前扩容，减少多次重新分配。
- `resize(n)` 改变元素数量，可能构造或析构元素；`reserve(n)` 只改变容量，不改变 size。

## 六、面试速答

- `struct` 和 `union`：前者成员独立存储，后者成员共享存储。
- 内存对齐：为了满足硬件访问要求和提升访问效率，结果由类型对齐、ABI 和编译器规则决定。
- `new/delete` 和 `malloc/free`：前者管理对象生命周期，会调用构造析构；后者只处理原始内存。
- `std::move`：只是转成右值，不保证发生移动。
- `std::forward`：在模板中保留参数的左值/右值属性。
- 拷贝构造参数：必须用引用，否则会递归调用拷贝构造。
- 基类析构：作为多态基类时应使用虚析构。
- `shared_ptr`：解决共享所有权，不解决对象本身线程安全。
- `vector` 扩容：增长倍率实现相关，扩容会导致迭代器等失效。
