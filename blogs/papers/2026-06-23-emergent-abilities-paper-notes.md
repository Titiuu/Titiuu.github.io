# 经典论文解读｜Scaling 与涌现（三）：Emergent Abilities of Large Language Models

2022 年，Jason Wei 等发表了 **《Emergent Abilities of Large Language Models》**。

如果说 Kaplan scaling law 告诉我们“语言模型的 loss 会随着规模平滑下降”，Chinchilla 论文告诉我们“参数和 token 要按更合理的比例增长”，那么这篇论文关注的是另一个更让人不安的问题：

> 为什么有些下游能力看起来不是平滑变好，而是到了某个规模之后突然出现？

论文把这种现象称为 **emergent abilities**，也就是大语言模型的涌现能力。它的定义很直接：小模型不具备、但大模型具备的能力，并且不能简单通过小模型上的趋势外推出大模型表现。

本文按四个问题展开：

1. 为什么大模型时代需要讨论“涌现”？
2. 作者们到底做了什么？
3. 论文观察到了哪些结果？
4. 这篇论文后来产生了什么影响，又引发了哪些争议？

---

## 一、研究背景：Scaling law 之外的“不连续感”

在 2020 到 2022 年之间，大模型研究里有一个越来越强的共识：规模很重要。

GPT-3 展示了 few-shot prompting 的潜力，Kaplan 等人的 scaling law 给出了一组可外推的经验规律，Chinchilla 又进一步讨论了固定算力下模型参数量和训练 token 数应该如何配平。对于预训练 loss 来说，这些工作传达的信号很清楚：

```text
模型更大、数据更多、算力更多 -> loss 通常更低
```

这是一种平滑的工程图景。只要预算允许，我们可以训练一批小模型，拟合曲线，再估计更大模型可能达到的 loss。

但下游任务的表现并不总是这么平滑。

### 1. 有些能力像是“过阈值”之后才出现

在很多任务上，小模型不只是表现差，而是接近随机猜测。继续扩大模型一段时间，指标仍然没有明显变化。然后，当模型规模跨过某个范围后，性能突然明显高于随机水平。

这种曲线和经典 scaling law 的直觉不同：

| 观察对象 | 常见曲线形态 | 直观含义 |
| --- | --- | --- |
| 预训练交叉熵 loss | 随规模平滑下降 | 规模收益可预测 |
| 某些下游任务准确率 | 长时间接近随机，随后跃升 | 能力像是突然出现 |

论文把这种现象放进更宽泛的“涌现”概念里。作者引用的基本思想是：系统的量变可能导致行为上的质变。对语言模型来说，量变就是训练计算量、参数量、数据规模等因素；质变则是模型开始完成以前做不了的任务。

### 2. 这对大模型研发很关键

讨论涌现不是为了制造神秘感，而是因为它直接影响研发判断。

如果能力提升总是平滑的，我们可以用小模型实验预测大模型。但如果某些能力只有在足够大时才出现，小模型实验就可能低估继续扩展的价值。

举个例子：如果 1B、10B 模型都做不好某个任务，我们能否判断这个任务不适合语言模型？涌现论文给出的提醒是：不能太快下结论。某些任务可能只是还没有跨过规模阈值。

这也解释了为什么 2022 年前后，大模型社区开始特别关注 BIG-Bench、MMLU、TruthfulQA、chain-of-thought 等评测和 prompting 方法。大家不只是在问“模型平均分有没有更高”，而是在问：

> 模型规模变大之后，会不会打开一组此前看不到的新能力？

## 二、作者做了什么：不是训练一个新模型，而是系统整理证据

这篇论文不是一篇“我们训练了一个更强模型”的论文。它更像一篇概念论文和综述论文：作者收集已有模型家族、已有 benchmark 和已有 prompting 方法中的例子，讨论哪些现象可以被称为涌现能力。

论文中的模型包括 GPT-3、LaMDA、Gopher、Chinchilla、PaLM 等。作者主要把模型规模放在两个轴上理解：

- 训练计算量，也就是 training FLOPs。
- 模型参数量。

论文更偏好用 training FLOPs 作为横轴，因为参数量不是唯一的规模因素。比如 Chinchilla 参数量小于 Gopher，但训练 token 更多、训练计算相近；稀疏 MoE 模型的参数量和实际计算量也不能简单等同。

### 1. 定义涌现能力

论文给出的操作性定义是：

> 一个能力如果在小规模模型中不存在，但在大规模模型中存在，就可以称为涌现能力。

在曲线上，它通常表现为：

```text
小模型：接近随机水平
中等模型：仍然接近随机水平
大模型：明显高于随机水平
```

这里的重点不是“大模型更好”，而是“小模型表现无法直接预测大模型会突然变好”。

### 2. 第一类证据：few-shot prompting 任务

论文首先讨论 GPT-3 推广起来的 few-shot prompting 范式：模型不做梯度更新，只在上下文里给几个输入输出示例，然后要求它完成新样本。

作者列举了多类任务：

| 任务类型 | 典型 benchmark / 例子 | 涌现现象 |
| --- | --- | --- |
| 算术 | BIG-Bench 中的多位数加减乘 | 小模型接近零，大模型突然超过随机 |
| 音标转写 | IPA transliteration | 规模足够大后 BLEU 明显上升 |
| 单词重排 | Word unscramble | exact match 在大模型上跃升 |
| 波斯语问答 | Persian QA | 大模型出现明显可用能力 |
| 多任务知识理解 | MMLU | 约 10B 以下模型平均接近猜测，更大模型明显超过随机 |
| TruthfulQA | 真实性问答 | Gopher 最大模型上出现高于随机的表现 |
| WiC | Word in Context | GPT-3 和 Chinchilla 未明显解决，PaLM 进一步放大后出现高于随机表现 |

这些例子的共同点是：下游指标不是随规模线性爬升，而是有明显的“起跳点”。

### 3. 第二类证据：增强 prompting 和微调策略本身也会涌现

更有意思的是，论文不只把“任务能力”看成涌现，也把某些“使用模型的方法”看成可能涌现。

比如 chain-of-thought prompting。对小模型来说，让它写中间推理步骤可能没帮助，甚至可能干扰答案；但当模型足够大时，中间推理步骤开始显著提升数学题表现。

论文还列举了几类类似现象：

| 方法 | 直观含义 | 涌现点 |
| --- | --- | --- |
| Chain-of-thought prompting | 先写推理步骤，再给答案 | 只在足够大模型上明显提升数学推理 |
| Instruction tuning | 用指令形式任务微调 | 小模型可能受损，大模型才明显受益 |
| Scratchpad | 训练模型写中间计算状态 | 计算任务上到一定规模后才有效 |
| Self-consistency | 多次采样推理链再投票 | 建立在大模型能产生有效推理链之上 |
| Calibration via P(True) | 让模型判断自己答案是否正确 | 在较大模型上更有效 |

这点很重要。它说明“涌现”不一定只是模型内部突然长出某个任务模块，也可能表现为：某种交互方式、训练方式或解码方式，只有在模型能力达到一定底座后才开始释放价值。

可以用一个简化图来理解：

```mermaid
flowchart LR
    Scale["规模扩大<br/>参数 / 数据 / 训练计算"] --> Base["基础语言建模能力提升"]
    Base --> Prompt["few-shot / CoT / instruction tuning"]
    Prompt --> Metric["下游任务指标"]
    Metric --> Jump["看起来突然跃升"]
    Base --> Risk["风险能力也可能变化"]
```

## 三、核心结果：涌现既真实重要，也需要谨慎解释

论文最直接的结果是：作者系统整理了一批在大模型中出现、在小模型中不明显的能力，并把它们作为一个值得研究的现象提出。

但这篇论文更有价值的地方，不只是列了很多例子，而是提出了几个后续研究绕不开的问题。

### 1. 规模阈值不是固定常数

论文没有声称某个能力一定在 10B、70B 或 100B 参数处出现。相反，作者明确提醒：涌现发生的规模取决于很多因素。

这些因素包括：

- 训练数据的质量和组成。
- 训练 token 数是否足够。
- 模型架构和 tokenizer 细节。
- 预训练目标。
- prompt 设计和评测方式。
- 指标是否给部分正确答案 credit。

这也是为什么 Chinchilla 和 PaLM 这样的例子很有启发性。参数量不是唯一答案。Chinchilla 参数更少但训练更充分，PaLM 可能因为训练数据、代码数据、多语言数据、数字编码等差异，在一些任务上比此前模型更早出现能力。

所以“涌现能力”更准确的理解不是：

```text
某能力 = 到某个参数量必然出现
```

而是：

```text
某能力 = 在若干相关规模变量共同提高后，可能从不可见变得可见
```

### 2. 多步推理和世界知识可能更容易表现出阈值

论文讨论了一些可能解释，但没有给出确定机制。

一个直觉是，多步推理任务需要模型连续完成多个中间步骤。如果每一步成功率都只是略微提高，最终答案准确率可能长期很低；只有当每一步的可靠性都超过一定水平时，最终指标才会明显上升。

另一个直觉是，闭卷问答、MMLU 这类任务需要模型在参数中压缩大量世界知识。模型太小时，知识覆盖不足，表现接近随机；模型更大、训练更多后，知识密度和调用能力同时改善，指标才开始显著变化。

但这些仍然是解释方向，不是定论。论文自己也承认：目前还缺少足够有说服力的机制解释，能够提前预测某个能力会在什么规模出现。

### 3. 评测指标可能放大“突然出现”的观感

这是理解这篇论文时最需要谨慎的地方。

很多下游指标是非连续的，尤其是：

- exact match：只有完全匹配才算对。
- multiple-choice accuracy：只有选项概率最高的答案算对。
- 最终答案 accuracy：多步推理里中间步骤部分正确也不给分。

这会导致一个现象：模型内部的 token 概率可能一直在平滑改善，但最终指标看起来像突然跳变。

比如一个多 token 答案，每个 token 的正确概率都从 0.6 慢慢提高到 0.8。单 token 层面是平滑变化，但如果指标要求整句完全正确，整体 exact match 可能会在某个区间突然变得可见。

论文也注意到了这一点，并在讨论中承认：某些指标可能遮蔽了小模型上的增量改进。不过作者认为，这个解释还不足以完全解释所有涌现现象，特别是一些分类任务和中间推理质量的变化。

## 四、后续影响：从“规模信仰”到“评测科学”

这篇论文的影响很大，因为它给 2022 年前后的大模型经验一个清晰名字：涌现能力。

这个名字本身很有力量。它让研究者、工程团队和产品团队开始用新的方式看待扩展模型：

> 继续 scaling 不只是把已有能力做得更好，也可能打开此前不可见的新能力。

### 1. 推动了更系统的大模型评测

涌现论文强化了 BIG-Bench、MMLU、TruthfulQA 等 benchmark 的重要性。传统 NLP benchmark 往往关注单个任务的平均指标，而大模型评测开始关注更宽的问题：

- 哪些任务在小模型上接近随机？
- 哪些任务会随着规模突然超过随机？
- prompt、CoT、self-consistency、instruction tuning 是否改变能力边界？
- 能力提升是否伴随新的风险？

这也是后来大模型报告越来越长、benchmark 越来越多的原因之一。一个模型的能力不再能靠单一 perplexity 或单一分类准确率概括。

### 2. 强化了 prompting 作为研究对象

在 GPT-3 之后，prompting 已经很重要；但涌现论文进一步说明，prompting 方法本身可能有规模门槛。

这对 chain-of-thought 尤其关键。小模型无法稳定利用“让我们一步步思考”这类提示，并不说明这个方向无效；它可能只是需要足够强的底座模型。后来围绕 CoT、self-consistency、least-to-most prompting、tool use、agent workflow 的大量研究，都可以放在这个脉络下理解。

模型不是一个孤立函数。模型规模、提示方式、推理时计算、外部工具和评测指标会共同决定最终能力。

### 3. 引入了安全层面的“未知未知”

如果正向能力可能涌现，风险能力也可能涌现。

论文在讨论中提到，偏见、毒性、记忆训练数据、欺骗性行为、后门等风险，都可能随规模变化。它没有声称这些风险都严格符合涌现定义，但强调了一点：当能力边界不能完全由小模型外推时，安全评测也不能只依赖小模型实验。

这对后来的安全研究影响明显。大模型越强，评测就越需要覆盖：

- 模型是否更会遵循恶意指令。
- 模型是否更容易泄露训练数据。
- 模型是否更会生成有害内容。
- 模型是否出现更强的策略性行为。
- 对齐方法是否也有规模门槛。

这让“预发布评测”和“能力预测”变成大模型部署前的重要环节。

### 4. 也引发了“涌现是不是幻觉”的争议

2023 年，Schaeffer、Miranda 和 Koyejo 发表 **《Are Emergent Abilities of Large Language Models a Mirage?》**，对涌现能力提出了强批评。

他们的核心观点是：很多所谓涌现能力，可能主要来自研究者选择的指标，而不是模型行为真的发生了不可预测的突变。尤其是 exact match、multiple choice grade 这类非线性或不连续指标，可能把平滑的 per-token 改善扭曲成突然跃升。

这篇后续论文做了几件事：

- 用数学模型说明平滑 loss 经过非线性指标后，可以呈现突变。
- 分析 BIG-Bench 中的任务和指标，指出许多涌现现象集中在少数指标上。
- 把指标换成更连续的度量后，一些涌现现象会消失。
- 在视觉任务中通过改变指标人为制造类似“涌现”的曲线。

这并不意味着 Wei 等人的论文没有价值。更准确的理解是：

| 观点 | 合理部分 | 需要警惕的部分 |
| --- | --- | --- |
| 涌现论文 | 提醒我们小模型趋势可能低估大模型能力 | 容易把指标跃升解释成能力本体突变 |
| Mirage 批评 | 强调指标选择会制造突变观感 | 不等于所有能力变化都只是指标幻觉 |

今天再看，“涌现能力”最好被理解为一个研究问题，而不是一个已经完全解释清楚的结论。

## 五、我的理解：涌现不是魔法，而是能力、指标和交互方式的交界面

这篇论文最值得保留的洞见，是它把大模型研究从“平均性能提高”推进到了“能力边界变化”。

对于工程和研究来说，一个能力是否涌现，至少要拆成三层：

### 1. 模型内部能力是否在平滑改善？

预训练 loss、目标序列 log-likelihood、token 级概率可能一直在平滑变好。小模型不是真的完全没有学习，只是学习程度不足以跨过下游指标的判定线。

### 2. 外部指标是否制造了阈值？

exact match、accuracy、pass/fail 这类指标天然会制造阈值感。它们对产品很有意义，因为用户最终确实关心“对还是错”；但它们不一定适合解释模型内部能力如何增长。

所以做研究时，最好同时看：

- 最终答案准确率。
- token-level loss 或 log probability。
- 部分正确度量。
- 中间推理步骤质量。
- 不同 prompt 下的稳定性。

### 3. 使用方法是否也需要足够强的底座？

CoT、instruction tuning、self-consistency、工具调用、agent 工作流，本质上都是建立在模型已有能力之上的放大器。底座太弱时，放大器可能放大噪声；底座足够强时，它们才会放大能力。

这解释了很多实践经验：同一个 prompt 技巧，在小模型上像玄学，在大模型上突然变成可靠工具。

---

## 六、结论：这篇论文改变了我们提出问题的方式

《Emergent Abilities of Large Language Models》的经典之处，不在于它证明了“规模会自动带来一切智能”。它真正改变的是问题意识。

在它之前，很多讨论集中在：

```text
模型变大，平均指标能提高多少？
```

在它之后，大家更认真地问：

```text
模型变大，会不会出现以前看不到的能力？
这些能力是真正的行为变化，还是评测指标造成的表象？
哪些能力可以通过数据、训练、架构、prompt 或工具提前解锁？
哪些风险也会随规模突然显现？
```

这也是今天理解大模型最重要的视角之一：规模不是唯一因素，但规模会改变研究问题本身。涌现能力既不是神秘魔法，也不能被简单否定为幻觉。它更像一个提醒：当系统足够复杂时，我们需要同时研究模型、数据、训练、提示、指标和风险，而不是只盯着一条平滑的 loss 曲线。
