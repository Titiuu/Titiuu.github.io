# 经典论文解读（八）｜对齐与微调：Training Language Models to Follow Instructions with Human Feedback

大规模预训练让语言模型拥有了越来越强的生成、问答和推理能力，但能力更强，不等于更愿意按照用户的意图行动。

预训练模型学习的是：

```text
给定前文，什么 token 最可能接在后面？
```

而用户真正关心的是：

```text
这个回答是否理解了我的要求？
是否有帮助、真实，并且不会造成伤害？
```

这两个目标并不相同。互联网文本中存在错误信息、有害内容、互相矛盾的观点和大量并非问答形式的文本。即使扩大模型规模，下一个 token 预测也不会自动变成“按照用户意图提供可靠帮助”。

2022 年，Ouyang 等人在 **《Training Language Models to Follow Instructions with Human Feedback》** 中系统展示了 InstructGPT：先用人类示范进行监督微调，再从人类对模型回答的排序中训练奖励模型，最后通过强化学习优化语言模型的行为。

> InstructGPT 的关键贡献，不是发明 RLHF，而是把人类示范、偏好建模和强化学习整合成一套面向通用语言模型的后训练流程，使“模型如何回应用户”成为独立于预训练能力的优化目标。它不仅是 ChatGPT 的重要技术前奏，也奠定了此后主流 LLM“预训练—指令微调—偏好或奖励优化”的基本训练范式。

本文按六个问题展开：

1. 为什么预训练模型不等于可用的语言助手？
2. SFT、奖励模型和 PPO 分别解决什么问题？
3. 怎样把人类排序转化成模型可以优化的奖励？
4. 为什么 PPO 还需要 KL 约束和预训练数据？
5. 论文用什么证据说明 RLHF 有效？
6. 这套流程为什么影响了此后的 LLM 训练？

---

## 一、从“生成语言”到“符合用户意图”

GPT-3 已经展示了强大的 few-shot 能力。用户可以通过 prompt 和少量示例让模型执行翻译、摘要、问答等任务，但它仍经常误解要求、编造事实、生成无关内容，甚至延续提示中的偏见与有害模式。

InstructGPT 论文把这个问题描述为语言模型与用户意图之间的 **misalignment**。

论文采用了 helpful、honest、harmless 三个方向来描述理想行为：

| 目标 | 含义 | 典型失败 |
| --- | --- | --- |
| Helpful | 理解并完成用户任务 | 答非所问、忽略格式要求、拒绝正常请求 |
| Honest | 不欺骗，不把未知内容伪装成事实 | 幻觉、迎合错误前提、虚构来源 |
| Harmless | 避免造成不合理伤害 | 提供危险建议、仇恨或滥用内容 |

不过，这三个目标并没有天然对应一个可计算的损失函数。

分类任务可以用准确率，语言建模可以用交叉熵，但“这个回答是否真正有帮助”通常取决于上下文、用户意图和人的判断。即使能列出一组规则，也很难穷举所有任务与失败模式。

RLHF 的基本想法是：既然很难直接写出“好回答”的目标函数，就让人类通过示范和比较表达判断，再训练模型近似这种判断。

### 1. 能力和行为是两条不同的轴

InstructGPT 最值得记住的转变，不是用对齐取代 scaling，而是把模型训练拆成两个互补问题：

```text
预训练：模型能做什么？
后训练：模型面对用户时会做什么？
```

一个模型可能拥有回答问题的知识，却不知道用户希望它直接给出结论；也可能具备翻译能力，却继续补全 prompt 而不是执行翻译要求。

后训练的作用，就是改变能力的调用方式与外显行为。它既是对齐研究的一部分，也是把基础模型转化为实际产品的工程层。

## 二、InstructGPT 的三阶段训练流程

InstructGPT 从 GPT-3 的 1.3B、6B 和 175B 三种参数规模开始。预训练已经完成，论文研究的是如何通过人类反馈继续塑造这些模型。

```mermaid
flowchart LR
    GPT["预训练 GPT-3"] --> SFTData["人类编写理想回答"]
    SFTData --> SFT["阶段一：SFT 模型"]

    SFT --> Samples["对同一 Prompt 生成多个回答"]
    Samples --> Ranking["人类对回答排序"]
    Ranking --> RM["阶段二：训练奖励模型"]

    SFT --> Policy["阶段三：PPO 策略初始化"]
    RM --> Reward["为新回答提供奖励"]
    Reward --> Policy
    Policy --> InstructGPT["InstructGPT / PPO-ptx"]
```

这不是三种互相替代的方法，而是一个逐步建立目标的闭环：

- 人类示范解决冷启动问题。
- 人类比较把回答质量转化为可学习的偏好信号。
- 奖励模型把有限的人类比较推广到更多新回答。
- PPO 根据这个代理奖励继续优化语言模型。

### 1. 阶段一：监督微调 SFT

首先，标注员阅读 prompt，并编写他们认为理想的回答。这些 `(prompt, demonstration)` 样本被用于监督微调 GPT-3，得到 SFT 模型。

论文中的 prompt 来自两类来源：

- 标注员根据要求人工编写，包括普通任务、few-shot 任务和模拟 API 用例的任务；
- 用户提交给早期 InstructGPT API Playground 的真实 prompt，在过滤个人身份信息后用于训练。

SFT 数据集约有 **13k 个训练 prompts**，覆盖生成、开放问答、对话、摘要、抽取和分类等多种用途。

从训练形式看，SFT 仍然是标准语言模型微调：给定 prompt 和人类回答，最大化人类回答 token 的似然。

```text
Prompt：给六岁孩子解释登月。
Human demonstration：一段简短、准确、适合儿童的回答。
```

SFT 让模型学会基本的指令—回答格式，也为后续强化学习提供一个相对稳定的初始策略。直接从未经指令微调的 GPT-3 开始探索，模型会产生大量格式错误或低质量输出，使奖励学习更困难。

但示范数据有明显成本：标注员必须亲自写出完整的高质量回答。对于复杂问题，“从零写出最佳答案”通常比“比较几个现有答案哪个好”更耗时。

### 2. 阶段二：训练奖励模型 RM

第二阶段不再要求标注员编写答案。研究者让模型针对同一个 prompt 生成多个回答，再让标注员按质量排序。

```text
同一个 Prompt
  |-- 回答 A
  |-- 回答 B
  |-- 回答 C
  |-- 回答 D
        ↓
人类排序：C > A > D > B
```

论文每次向标注员展示 4–9 个模型回答。一个排序可以拆成多个成对偏好，例如：

```text
C 胜过 A
C 胜过 D
C 胜过 B
A 胜过 D
A 胜过 B
D 胜过 B
```

这些比较构成约 **33k 个训练 prompts** 的 RM 数据集。研究者用它训练一个奖励模型 `r(x, y)`：输入 prompt `x` 和回答 `y`，输出一个标量，表示这个回答被标注员偏好的程度。

### 3. 阶段三：用 PPO 优化策略

有了奖励模型后，模型可以对约 **31k 个未标注 API prompts** 反复生成回答。奖励模型为回答打分，PPO 再更新语言模型，让高奖励回答的概率提高。

这个强化学习环境其实很简单，更接近 contextual bandit：

1. 环境给出一个用户 prompt。
2. 策略模型生成完整回答。
3. 奖励模型对 `(prompt, answer)` 给出一次分数。
4. 本轮结束，PPO 更新策略。

最终得到的 PPO-ptx 模型，就是论文通常所称的 InstructGPT。

## 三、奖励模型如何学习人的偏好？

奖励模型并不知道什么是真理或普遍价值。它学习的是：面对同一个 prompt，标注员更可能选择哪个回答。

设 `y_w` 是人类更偏好的回答，`y_l` 是较差回答，奖励模型分别输出：

```text
r(x, y_w)
r(x, y_l)
```

论文使用类似 Bradley–Terry 模型的成对偏好概率：

```math
P(y_w > y_l | x) = sigmoid(r(x, y_w) - r(x, y_l))
```

对应的训练损失可以简化写成：

```math
L_RM = -log(sigmoid(r(x, y_w) - r(x, y_l)))
```

如果标注员选择了 `y_w`，训练就推动 `r(x, y_w)` 高于 `r(x, y_l)`。奖励的绝对数值没有直接含义，重要的是两个回答之间的差值。

### 1. 为什么比较比直接打分更合适？

让人给回答打“82 分”很难保持一致：不同标注员对分数尺度的理解不同，同一个人在不同时间也可能改变标准。

而回答“这两个答案哪个更好”通常容易一些。它允许人类综合考虑多个难以形式化的因素：

- 是否正确理解指令；
- 是否完成用户任务；
- 是否准确、清晰和相关；
- 是否遵守长度、格式等显式约束；
- 是否包含不必要的有害内容。

奖励模型把大量局部比较压缩成一个可以反复调用的评分器。人不需要参与每次 PPO 更新，这使偏好优化能够扩展到远多于人工标注数量的模型回答。

### 2. 奖励模型是代理目标，不是人类价值本身

这里也产生了 RLHF 的核心风险：PPO 优化的不是人类偏好，而是**奖励模型对人类偏好的预测**。

```text
真实目标：人类认为回答有帮助、真实且无害
代理目标：奖励模型给出的标量分数
```

当策略模型生成的回答逐渐偏离奖励模型的训练分布时，就可能找到奖励模型的漏洞。某些回答可以获得高预测奖励，却不一定真正受人喜欢。这就是 reward hacking 或 reward overoptimization 的来源之一。

因此，RLHF 不能只靠“最大化奖励”四个字完成，它还需要限制优化幅度。

## 四、PPO 为什么还需要两道约束？

论文的强化学习目标不只是奖励模型分数，还加入了对 SFT 模型的 KL 惩罚：

```math
reward = r(x, y) - beta * log(pi_RL(y|x) / pi_SFT(y|x))
```

其中：

- `r(x, y)` 是奖励模型对回答的评分；
- `pi_RL` 是正在优化的策略；
- `pi_SFT` 是监督微调后的参考策略；
- KL 项惩罚策略过度偏离 SFT 模型。

### 1. KL 惩罚：不要为了奖励走得太远

SFT 模型至少处于人类示范附近，而奖励模型只在有限比较数据上训练。若 PPO 不受约束地最大化奖励，策略就可能进入奖励模型没有可靠判断能力的区域。

KL 惩罚相当于告诉模型：

> 可以向更受偏好的方向调整，但不要为了几分奖励，彻底离开人类示范建立的行为分布。

这既降低 reward hacking，也帮助维持语言流畅性和基本任务能力。

### 2. PPO-ptx：不要忘记预训练能力

最初的 PPO 实验在 SQuADv2、DROP 等公开 NLP 数据集上出现性能回退。模型变得更符合标注员偏好，却损失了部分预训练能力。论文把这种代价称为 **alignment tax**。

为缓解它，作者在 PPO 梯度之外混入一项预训练语言模型目标：

```math
objective = RLHF_reward + gamma * pretraining_log_likelihood
```

这就是 **PPO-ptx**：

- RLHF 更新塑造模型面对用户时的行为；
- 预训练更新提醒模型保留原有的语言和任务能力。

实验显示，混合预训练梯度能够显著缓解公开 NLP 任务上的性能退化，同时基本不牺牲人类偏好结果。

KL 与 ptx 看起来都在“防止模型偏离”，但作用并不完全相同：

| 约束 | 参考对象 | 主要目的 |
| --- | --- | --- |
| KL penalty | SFT 策略在当前 prompt 上的输出分布 | 限制策略漂移与奖励过度优化 |
| Pretraining mix | 原始预训练数据分布 | 保留更广泛的语言建模与下游能力 |

这也说明 InstructGPT 的贡献不是简单套用 PPO。真正有效的是一套由人类数据、奖励代理和优化约束组成的系统。

## 五、实验结果：对齐不能被参数规模替代

论文最醒目的结果是：在人类偏好评估中，标注员更喜欢 **1.3B InstructGPT** 的回答，而不是 **175B GPT-3** 的回答，尽管前者参数量少了 100 多倍。

这不意味着 1.3B 模型在知识、推理和所有 benchmark 上全面超过 175B 模型。它证明的是一个更具体、也更重要的结论：

> 参数规模和符合用户意图是不同的优化方向。更大的 raw model，不会自动变成更好的语言助手。

### 1. 人类偏好逐阶段提升

论文比较了 GPT-3、经过精心 few-shot prompting 的 GPT-3、SFT、PPO 和 PPO-ptx。总体结果呈现出清晰的阶段性改善：

```text
Raw GPT-3
  → 使用 few-shot prompt
  → SFT 学习人类示范
  → PPO 学习人类比较
```

175B InstructGPT 与同规模 GPT-3 直接比较时，回答有 **85 ± 3%** 的概率被标注员偏好；与经过 few-shot prompting 的 175B GPT-3 比较时，偏好率仍达到 **71 ± 4%**。

标注员还认为 InstructGPT：

- 更能尝试正确的任务；
- 更常遵守明确的长度和格式要求；
- 输出更适合作为面向客户的助手回答；
- 在摘要、封闭域问答等任务中更少编造输入之外的信息。

### 2. 真实性改善，但安全结果并不整齐

在 TruthfulQA 上，InstructGPT 生成既真实又有信息量回答的频率约为 GPT-3 的两倍。在封闭域 API 任务中，论文报告的幻觉率从 GPT-3 的 41% 降至 InstructGPT 的 21%。

毒性方面，模型在被明确要求保持尊重时，生成的有毒内容比 GPT-3 少约 25%。但论文没有观察到偏见指标上的显著改善，其他有害内容类别也并非都出现显著变化。

因此，正确结论不是“RLHF 解决了安全”，而是：在特定 prompt、评价规范和代理指标下，人类反馈改善了若干有用性、真实性与毒性行为。

### 3. Held-out 标注员仍然偏好 InstructGPT

为了检查模型是否只拟合训练标注员，论文另外邀请没有参与训练数据生产的标注员进行评价。他们对 InstructGPT 与 GPT-3 的相对偏好，与训练标注员大致一致。

奖励模型预测 held-out 标注员偏好的准确率约为 69.6%，相比在训练标注员数据上的 72.4% 只小幅下降。这说明偏好信号具有一定人群外泛化能力，但也远未达到“代表所有人”的程度。

## 六、谁的反馈？对齐了什么？

“Reinforcement Learning from Human Feedback”中的 human 很容易制造一种错觉：仿佛模型正在对齐全人类共同认可的价值。

论文对此非常明确：这套流程让模型更符合**特定标注员与研究者群体表达的偏好**，而不是某种普遍的人类价值。

### 1. 偏好来自有限人群与规则

标注员需要通过筛选测试，并按照研究团队提供的指南工作。这有助于提高一致性，但也意味着奖励模型学习的是一套经过制度化的数据生产过程。

论文数据超过 96% 是英文，prompt 主要来自特定时期的 API Playground 用户。不同文化、语言、专业背景和使用场景中的人，可能对“帮助”“伤害”和“合适回答”持有不同判断。

即使 held-out 标注员结果相近，也只能说明模型泛化到来源相似的另一批评价者，不能证明它代表更广泛人群。

### 2. Helpful、Honest、Harmless 可能互相冲突

如果用户要求生成危险操作指南，“遵循用户意图”会与“避免伤害”发生冲突。模型应该直接帮助、拒绝回答，还是提供有限的安全信息？这不是一个仅凭回答排序就能自动解决的问题。

论文的数据收集优先训练 helpfulness，没有专门让模型普遍拒绝有害指令。因此 InstructGPT 仍可能执行危险请求。作者也指出，提高指令遵循能力甚至可能让模型更容易被滥用，例如生成更有说服力的虚假信息。

这揭示了对齐工程中的基本张力：

```text
用户想要什么
    ≠
系统在所有情境下都应该做什么
```

### 3. 更受偏好不等于可以信任

InstructGPT 仍会：

- 接受问题中的错误前提；
- 编造事实；
- 对简单问题过度保留；
- 在包含多个约束的指令上退化；
- 生成有害或带偏见的回答。

RLHF 改善的是给定数据分布上的平均行为，不提供真实性或安全性的形式保证。更自然、更自信的表达甚至可能让错误更难被用户察觉。

因此，这篇论文迈向的是“更值得协作的系统”，而不是已经建立了可以无条件信任的系统。

## 七、它没有发明 RLHF，但改变了 LLM 的训练方式

RLHF 并非从 InstructGPT 开始。此前工作已经将人类偏好用于 Atari 和机器人控制，也将奖励学习用于文本摘要、对话等任务。InstructGPT 自己明确建立在 Christiano et al. 2017、Ziegler et al. 2019 和 Stiennon et al. 2020 等工作的基础上。

它真正推进的是：**把 RLHF 从特定任务实验，整合成面向开放任务分布和真实用户 prompt 的通用语言模型后训练流程。**

### 1. ChatGPT 的重要技术前奏

ChatGPT 后来同样采用监督微调和 RLHF：人类训练者提供对话示范，再对模型回答排序，由奖励模型和强化学习继续优化行为。

但不应把 InstructGPT 与 ChatGPT 当成同一个系统。ChatGPT 面向多轮对话，模型底座、数据组织、产品目标和具体训练细节都有变化。更准确的说法是，InstructGPT 系统验证了 ChatGPT 所延续的核心后训练思路。

### 2. 此后主流 LLM 的共同骨架

InstructGPT 的影响也不限于 ChatGPT。此后许多主流语言模型都采用类似的分阶段结构：

```text
大规模预训练
  → 指令监督微调
  → 偏好或奖励优化
```

具体算法则不断变化：

- **DPO** 直接从 chosen/rejected 回答对优化策略，省去显式奖励模型和 PPO。
- **Llama 3** 的后训练结合 SFT、奖励模型、rejection sampling 和 DPO。
- **DeepSeek-V3** 在预训练后继续进行 SFT 与强化学习。
- 其他路线还会使用 AI feedback、规则奖励、可验证奖励或多个奖励模型。

因此，PPO 式 RLHF 并不是后来唯一的行业标准。真正延续下来的是更抽象的思想：

> 基础能力主要在预训练中获得；指令与偏好后训练负责选择、组织和约束这些能力面向用户时的行为。

### 3. 从单一目标走向两阶段工程

这并不意味着 AI 研究从此停止追求更强能力。Scaling、数据、架构和推理训练仍在持续发展。

变化在于，模型研究与产品开发不再只依赖一条预训练 loss 曲线。一个成功的通用模型需要同时回答：

| 能力工程 | 行为与对齐工程 |
| --- | --- |
| 模型知道什么？ | 模型何时应该表达这些知识？ |
| 模型能否完成任务？ | 模型是否理解并遵守用户要求？ |
| 如何扩大模型、数据和计算？ | 如何定义、收集并优化期望行为？ |
| 如何提高 benchmark 能力？ | 如何处理有用、真实和无害之间的冲突？ |

InstructGPT 的历史价值，正在于把第二列变成了一套可以收集数据、训练模型和进行实验的工程问题。

---

## 八、总结：能力之后，还需要塑造行为

如果用一句话概括 InstructGPT 论文，我会这样说：

> InstructGPT 的关键贡献，不是发明 RLHF，而是把人类示范、偏好建模和强化学习整合成一套面向通用语言模型的后训练流程，使“模型如何回应用户”成为独立于预训练能力的优化目标。

这套流程完成了三次转换：

```text
人类示范
  → 把理想行为变成监督数据

人类排序
  → 把模糊偏好变成可学习的奖励模型

奖励优化
  → 把有限反馈扩展为语言模型的行为变化
```

论文最重要的证据也不是某个传统 benchmark，而是 1.3B InstructGPT 在人类偏好上超过 175B GPT-3。它说明模型更强大与模型更符合用户意图，不是同一件事。

从那以后，“预训练—指令微调—偏好或奖励优化”逐渐成为主流 LLM 的基本训练骨架。DPO、rejection sampling、RLAIF 和可验证奖励改变了其中的算法，但没有改变那个根本分工：**预训练扩展能力，后训练塑造行为。**

这也让语言模型的目标向前走了一步。我们不只希望模型能够生成语言，还希望它能够理解人的要求，在复杂约束中做出合适反应，并成为人可以协作、学习和逐步建立信任的系统。

InstructGPT 没有完成这个目标。它甚至让我们更清楚地看到：偏好属于谁、奖励是否可靠、有用与无害如何权衡，都是无法仅靠扩大模型规模解决的问题。

但它把这些问题从抽象原则变成了训练管线中的具体对象。这正是它开启“对齐工程”时代最重要的意义。
