# 经典论文解读（十）｜对齐与微调：QLoRA: Efficient Finetuning of Quantized LLMs

上一篇《LoRA》里我们算过一笔账：LoRA 把 GPT-3（175B）的微调显存从约 1.2TB 降到 350GB，checkpoint 从 350GB 降到 35MB。可这 350GB 里，绝大部分不是 LoRA 适配器，而是**冻结的 base 模型权重**——它们以 16-bit 精度常驻显存，一动不动。

为什么冻结的权重不能省一点？LoRA 训练时，整个 base 模型都要参与前向和反传，所以它必须以可计算的精度待在显存里。QLoRA 论文提出的问题正是：**如果反传只需要经过适配器，base 模型是不是可以用极低精度存储？**

2023 年，Dettmers 等人提出 **《QLoRA: Efficient Finetuning of Quantized LLMs》**：把冻结的 base 模型量化到 4-bit（NF4）存储，用时反量化回 16-bit 计算，梯度只流向 16-bit 的 LoRA 适配器。结果，65B 参数的模型可以在**单张 48GB GPU** 上微调（16-bit 全参微调需要超过 780GB），性能却不降。它训练出的 Guanaco 模型在 Vicuna benchmark 上达到 ChatGPT 的 **99.3%**。

> QLoRA 的关键贡献，是打破了 LoRA 里「冻结权重必须以 16-bit 常驻显存」的隐含前提：冻结权重不需要梯度，所以可以用 4-bit 存储、反量化到 16-bit 计算，梯度只流向适配器。它提出 4-bit NormalFloat（NF4）数据类型、双重量化（Double Quantization）和分页优化器（Paged Optimizers）三个组件，把 65B 级模型的微调从多机多卡拉到单张显卡。

本文按六个问题展开：

1. LoRA 之后，显存还浪费在哪？
2. 为什么冻结权重可以降到 4-bit？
3. NF4 是什么，为什么不是随便一种 4-bit 就行？
4. 双重量化和分页优化器各解决什么？
5. 实验证明了什么？
6. 它如何影响之后的微调生态，局限在哪？

---

## 一、LoRA 之后，显存还浪费在哪？

LoRA 解决了两个大头：全参微调要为每个参数存梯度与优化器状态（Adam 的动量和方差），以及为每个任务保存一份完整模型。但微调进行时，还有一笔固定开销 LoRA 没有动：**冻结的 base 模型本身**。

以 7B LLaMA 为例，论文给出了微调时的显存账单（FLAN v2、batch size 1）：

| 项目 | 显存 | 说明 |
| --- | --- | --- |
| 4-bit base 模型 | 5,048 MB | 冻结权重，几乎占全部 |
| LoRA 参数 | 26 MB | 约等于原模型 0.2% 的权重 |
| LoRA 输入梯度 | 567 MB → 18 MB | 开启梯度检查点（gradient checkpointing）后每序列平均 |

两个值得注意的点：

- **大头是 base 模型本身**。把 LoRA 适配器砍掉一半，省的显存是 26MB 级别；但 base 模型的存储是 GB 级别。显存优化的重点应该放在 base 模型上。
- **梯度检查点非常重要**。没有它，激活梯度的显存（567MB）反而超过所有 LoRA 权重（26MB）；开启后每序列平均降到 18MB。

更重要的是，这个账单暗示了一个此前没被利用的机会：**LoRA 适配器这么小，意味着可以加很多适配器而不显著增加显存**。LoRA 原本只改 Wq、Wv 两个矩阵，QLoRA 论文发现，在 7B 以上模型里只改 Wq/Wv 追不平 16-bit 全参微调，必须把 LoRA 加到**所有线性层**才够——而这在 QLoRA 的显存结构下几乎免费。

## 二、为什么冻结权重可以降到 4-bit？

这是 QLoRA 最核心的一个观察。

传统量化方法（GPTQ、LLM.int8() 等）只服务于**推理**：模型参数一次性量化，前向时低精度计算。它们「在训练中会崩溃」——因为训练要在权重上算梯度，量化误差会被反向传播放大，权重更新也依赖高精度表示。

LoRA 微妙地改变了这个局面。在 LoRA 训练中：

- 权重更新只发生在适配器 A、B 上（16-bit）；
- 反传只需要算适配器的梯度，**不需要算 base 权重的梯度**；
- 但适配器的梯度计算，需要前向（和反传）经过 base 模型的权重。

所以 base 模型需要的不是「可训练的高精度权重」，而是「足够精确的前向/反传结果」。QLoRA 的做法是：

```text
存储：W_NF4（4-bit）     ← base 权重以 4-bit 存显存
计算：W_BF16（16-bit）   ← 用时反量化回 BF16 做矩阵乘
更新：只更新 L1、L2      ← BF16 适配器
```

前向公式（单个线性层 + 单个适配器）：

```text
Y_BF16 = X_BF16 · doubleDequant(c1_FP32, c2, W_NF4) + X_BF16 · L1_BF16 · L2_BF16
```

- 第一项是反量化后的 base 投影，`doubleDequant` 负责把 4-bit 权重按两级量化常数还原成 BF16；
- 第二项就是 LoRA 的低秩分支；
- 核心是**存储精度与计算精度分离**：存储用 4-bit，计算用 16-bit。

这就是「LoRA 用的 16-bit，但 base 模型其实可以 4-bit 存」的完整版本：LoRA 适配器保持 16-bit——需要梯度的部分不能量化；可量化的是冻结的、不需要梯度的 base 权重。

## 三、NF4 是什么？为什么不是随便一种 4-bit 就行？

「4-bit 量化」听上去简单，但比特数只是约束，真正决定精度的是**数值怎么排布**。QLoRA 专门设计了一种 4-bit 数据类型：NormalFloat（NF4）。

### 1. 背景：逐块量化与分位数量化

把 32-bit 权重压到低比特，最朴素的做法是**逐张量缩放**：除以绝对最大值映射到目标区间。但若张量里有离群值，大多数数值会挤在很小的区间里，量化桶用不上。因此量化实践普遍用**逐块量化**（block-wise quantization）：把张量切成小块，每块各自算缩放常数。

更优的做法是**分位数量化**（quantile quantization）：让每个量化桶装进相同数量的数值。它信息论上最优，但估计分位数很贵，近似算法又会在离群值上出错。

### 2. NF4：对正态分布信息论最优的 4-bit 类型

论文的关键观察是：**预训练权重的分布近似零均值正态分布**（论文附录 F 有实证）。既然分布形态固定，分位数就可以提前算好，而不是运行时估计。

NF4 的构造：对标准正态分布 N(0,1) 求 2^k 个分位点的中点作为量化值：

```text
q_i = ( Q_X(i/(2^k+1)) + Q_X((i+1)/(2^k+1)) ) / 2
```

其中 `Q_X(·)` 是标准正态分布的分位数函数。取到的量化值再规范到 [-1,1]。这样一个 4-bit 数据类型对「零均值、任意标准差的正态权重」是信息论最优的——每个桶等概率地容纳数值。

NF4 还特意做成了**非对称**类型：负半轴 2^(k-1) 个值、正半轴 2^(k-1)+1 个值，这样能保证 0 有精确表示，量化 padding 时零误差。

### 3. 数值证据：NF4 显著优于 FP4 / Int4

论文在 Pile Common Crawl 上测了不同 4-bit 类型的平均困惑度（125M–13B 的 OPT/BLOOM/LLaMA/Pythia）：

| 数据类型 | 平均困惑度 |
| --- | --- |
| Int4 | 34.34 |
| Float4 (E2M1) | 31.07 |
| Float4 (E3M0) | 29.48 |
| NFloat4 + DQ | 27.41 |

「随便拿个 4-bit 量化来用」是不够的：Int4 和 FP4 都明显更差，只有 NF4 逼近 16-bit 的量化精度。这也是做 QLoRA 的要点之一——数据类型本身决定了能省掉多少精度损失。

## 四、双重量化和分页优化器各解决什么？

### 1. 双重量化（Double Quantization）

逐块量化有个隐藏开销：**每一块的缩放常数（quantization constant）本身也是 32-bit 浮点**。块越小、量化越精确，常数就越多。以块大小 64 为例：

```text
32-bit 常数 / 64 个权重 = 平均每个参数多 0.5 bit
```

这相当于把 4-bit 量化悄悄变成了 4.5-bit。双重量化就是**把这些常数再量化一次**：第一级量化常数 c2 用 8-bit FP、块大小 256 存储，第二级常数 c1 才保留 32-bit：

```text
平均开销：32/64 = 0.5 bits/param
        → 8/64 + 32/(64×256) = 0.127 bits/param
        省下约 0.373 bits/param
```

65B 模型约省 **3GB**。量化常数是正的，所以先减去均值再对称量化，能进一步利用 8-bit 的全部区间。

### 2. 分页优化器（Paged Optimizers）

微调长序列时，梯度检查点会产生**显存尖峰**，单机训练常常因此 OOM。分页优化器利用 NVIDIA unified memory：把优化器状态分配到可分页的显存里，GPU 显存不够时自动换出到 CPU、优化器更新时再换回——机制类似操作系统的内存分页。

论文测试了 65B 模型在 48GB GPU 上、batch size 16 的场景，分页优化器与普通优化器训练速度相同。它主要解决长序列极端场景下的 OOM 崩溃，而非提速。

## 五、实验证明了什么？

### 1. 4-bit QLoRA 追平 16-bit 微调（学术基准）

第一个问题：量化损失能不能靠适配器微调补回来？论文在 GLUE（RoBERTa-large）和 Super-NaturalInstructions（T5 80M–11B）上对比了 16-bit、8-bit、4-bit：

| 数据精度 | GLUE（RoBERTa-large） | Super-NI RougeL（T5-3B） | Super-NI RougeL（T5-11B） |
| --- | --- | --- | --- |
| BF16 全参微调 | 88.6 | 54.3 | 62.0 |
| LoRA BF16 | 88.8 | 55.4 | 60.7 |
| QLoRA Int8 | 88.8 | 56.5 | 60.7 |
| QLoRA FP4 | 88.6 | 55.6 | 60.9 |
| QLoRA NF4 + DQ | – | 55.3 | 60.9 |

结论：**量化后的适配器微调，能完整复现 16-bit 微调的性能**——量化丢失的精度被适配器微调补了回来。

### 2. 在大模型上，NF4 + DQ 匹配 16-bit LoRA（MMLU）

第二个问题：7B–65B 的大模型上，4-bit QLoRA 能匹配 16-bit LoRA 吗？论文在 Alpaca 和 FLAN v2 上微调 LLaMA 7B–65B，测 MMLU 5-shot（每格是 Alpaca / FLAN v2 两个数据集的结果）：

| 数据类型 | 7B | 13B | 33B | 65B | 平均 |
| --- | --- | --- | --- | --- | --- |
| BFloat16 | 38.4 / 45.6 | 47.2 / 50.6 | 57.7 / 60.5 | 61.8 / 62.5 | 53.0 |
| Float4 | 37.2 / 44.0 | 47.3 / 50.0 | 55.9 / 58.5 | 61.3 / 63.3 | 52.2 |
| NFloat4 + DQ | 39.0 / 44.5 | 47.5 / 50.7 | 57.3 / 59.2 | 61.8 / 63.9 | 53.1 |

- **NF4 + 双重量化平均追平 BFloat16（53.1 vs 53.0）**，且跨 7B–65B 四个规模都成立；
- **FP4 稳定落后约 1 个百分点**（52.2）——再次印证 NF4 的必要性。

论文还发现一个反直觉的点：**适配器放在哪些层，比秩 r 更重要**。默认只改 Wq、Wv 追不平 16-bit 性能，把 LoRA 加到所有线性层（论文用 r=64、α=16）才能匹配全参微调；而 r 的大小在「全层 LoRA」下几乎不影响最终性能。

### 3. 记忆足迹：从 >780GB 到单卡 48GB

| 模型 | 16-bit 全参微调 | QLoRA（4-bit + DQ） | 推理时占用 |
| --- | --- | --- | --- |
| LLaMA 7B | ~35GB | 单张消费级 GPU | 5GB |
| LLaMA 33B | >400GB | 24GB 消费级 GPU（<12 小时） | 21GB |
| LLaMA 65B | >780GB | 单张 48GB GPU（24 小时） | 41GB |

65B 的微调显存从「多机多卡才能搬动」降到「一张专业显卡」，这是 QLoRA 最直接的贡献。

### 4. Guanaco：微调出的 SOTA 开源聊天模型

论文用 QLoRA 在 8 个指令微调数据集上训练了 **1000+ 个模型**，最好的模型族叫 **Guanaco**（在 OASST1 数据集上微调），开源了 7B/13B/33B/65B 四个规模。在 Vicuna benchmark（GPT-4 评分，相对 ChatGPT 的性能百分比）：

| 模型 | 相对 ChatGPT 性能 |
| --- | --- |
| GPT-4 | 114.5% |
| **Guanaco 65B** | **99.3%** |
| **Guanaco 33B** | **97.8%** |
| Vicuna 13B | 94.9% |
| **Guanaco 13B** | **90.4%** |
| **Guanaco 7B** | **87.0%** |

在 Elo 擂台上（模型两两对决、GPT-4 判胜负），Guanaco 65B 和 33B 仅次于 GPT-4，**排在 ChatGPT 之前**（1022、992 vs ChatGPT 966）。

几个有意思的细节：

- **小模型也能打**：7B 的 Guanaco 推理只需 5GB，可以轻松放进手机，却比 26GB 的 Alpaca 13B 高出 20 多个百分点；
- **数据质量远大于数据量**：9k 样本的 OASST1 打败了 450k 样本的 FLAN v2（65B 上 Vicuna 99.3% vs 48.4%）。FLAN v2 擅长 MMLU 却对聊天任务极差——**MMLU 强不代表聊天强，反之亦然**；
- **只用开源数据**：Guanaco 是榜单前列里唯一没用 GPT 蒸馏数据训练的模型（OASST1 明确禁止用 GPT 模型生成）。

## 六、它如何影响之后的微调生态，局限在哪？

### 1. 影响

- **消费级 GPU 微调成为现实**。33B 可以塞进 24GB 消费卡、65B 一张 48GB 专业卡，普通研究者和个人第一次能微调当时最大的开源模型。
- **深度集成进主流工具链**。QLoRA 的代码与 CUDA 内核开源，并集成进 Hugging Face transformers / PEFT / bitsandbytes，成为 `load_in_4bit` 的默认实现。到今天，4-bit 量化微调仍是本地大模型微调的事实标准。
- **催生了一整套量化生态**。NF4 之后，GPTQ、AWQ 等推理量化方法继续发展，而「冻结权重极低精度 + 适配器高精度」的组合成了后续参数高效微调研究的常见底座。

### 2. 局限

论文自己的诚实话也要记下来：

- **没在 33B/65B 规模上验证「追平全参微调」**。QLoRA 与 16-bit 全参微调的对比只在 11B 及以下完成；33B/65B 上只对比了 16-bit LoRA，因为全参微调在这些规模成本太高。这是一个未被证明的边界。
- **评测基准的可信度存疑**。论文发现基准表现高度依赖微调数据与基准数据是否相似；模型评估存在顺序效应；GPT-4 给自己打分显著偏高。这也提醒我们，99.3% 这类数字要放在特定基准和评测协议下理解。
- **量化训练上限未知**。3-bit、更低精度是否仍能追平 16-bit，论文没有探索，留给后续研究。

---

## 总结

如果用一句话概括 QLoRA 论文，我会这样说：

> LoRA 已经把「需要梯度的部分」压到最小，QLoRA 则把「不需要梯度的冻结 base 权重」用 4-bit 存储。两者合在一起，65B 模型的微调从需要 >780GB 显存变成一张 48GB 显卡就能跑，性能还不降。

它完成了三次转换：

```text
冻结权重 16-bit 常驻显存
  → 4-bit（NF4）存储，反量化到 16-bit 计算

「随便一种 4-bit」量化
  → 信息论最优的 NormalFloat4，追平 16-bit 精度

微调大模型必须多机多卡
  → 65B 单卡 24 小时，7B 甚至能塞进手机
```

三个组件各司其职：**NF4** 决定量化精度（数据类型的排布比比特数更重要），**双重量化**抠掉量化常数那 0.37 bits/param，**分页优化器**兜住长序列的显存尖峰。而实验里最震撼的数字，是 Guanaco 65B 用 41GB 显存、单卡 24 小时训练，在 Vicuna benchmark 上拿下 ChatGPT 的 99.3%——质量、效率、规模第一次同时站在了开源这边。

当然也要保持审慎：QLoRA 追平的是 16-bit LoRA，而非所有规模下的全参微调；99.3% 依赖特定基准与 GPT-4 评测协议。它把「微调大模型的显存墙」几乎拆平，但评测基准的信任问题才刚刚开始被认真讨论。
