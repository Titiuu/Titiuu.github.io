# 经典论文解读（二）：Language Models are Unsupervised Multitask Learners

2019 年，Radford 等人在论文 **《Language Models are Unsupervised Multitask Learners》** 中发布了 GPT-2。今天回头看，这篇论文的意义不只是“模型更大了”，而是它把一个后来支配大模型时代的判断讲清楚了：

> 一个足够大的语言模型，只要在大规模、多样化文本上做无监督训练，就可能在不微调、不改参数的情况下，学会执行多种下游 NLP 任务。

这就是 GPT-2 论文里的核心命题：**语言建模本身可以成为无监督多任务学习**。

本文按四个问题展开：

1. 为什么当时的 NLP 系统缺乏通用性？
2. GPT-2 如何把“预测下一个词”变成多任务学习？
3. zero-shot 实验到底证明了什么？
4. 这篇论文为什么会影响后来的 GPT-3、指令微调和 scaling law？

---

## 一、研究背景：从窄域专家到通用模型

GPT-2 论文开篇批评的是当时 NLP 的主流范式：为每个任务收集标注数据，训练一个专门系统，再在同分布测试集上评估。

这种方法在很多 benchmark 上有效，但问题也很明显：它更像是在训练“窄域专家”，而不是训练能稳健适应新任务和新领域的通用系统。

### 1. 监督学习系统依赖任务定制

传统 NLP 任务通常长这样：

| 任务 | 常见做法 | 依赖 |
| --- | --- | --- |
| 阅读理解 | 在 SQuAD、CoQA 等数据集上监督训练 | 问答标注 |
| 机器翻译 | 在双语平行语料上训练 | 翻译对齐语料 |
| 摘要 | 在新闻和摘要配对数据上训练 | 文档-摘要标注 |
| 情感分类 | 在分类数据集上训练 | 类别标签 |

这套流程的问题不是不能工作，而是扩展性差。每来一个新任务，就要重新定义数据格式、收集标注、调模型，最后还要担心模型只学会了某个数据集的偏差。

GPT-2 论文提出的问题更激进：

> 如果一个系统真的理解自然语言，它是否必须为每个任务单独训练？

### 2. 多任务学习方向正确，但规模不足

多任务学习听起来是自然的出路：把多个任务放在一起训练，让模型学到更通用的表示。

但论文指出，当时的多任务 NLP 系统规模仍然很小。比如 decaNLP 和 MQAN 这类工作只整合了十几个 `(数据集, 目标)` 对。从元学习角度看，每个任务对都只是一个训练样本。如果希望模型从“任务分布”中学会泛化，十几个任务样本显然不够。

这就带来一个矛盾：

- 多任务学习需要大量任务。
- 人工构造大量任务和标注数据非常昂贵。
- 互联网上已经有海量自然语言文本，但它们不是标准监督数据。

GPT-2 的关键转向就在这里：不要再手工构造所有任务，而是让模型从自然文本里自己吸收任务示范。

### 3. 自然语言本身包含任务格式

自然文本并不是随机句子堆积。它里面经常天然出现“任务、输入、输出”的结构，例如：

```text
Q: Who wrote Origin of Species?
A: Charles Darwin.
```

```text
Translate to French:
Hello -> Bonjour
```

```text
Article: ...
Summary: ...
```

McCann 等人的 MQAN 已经证明，可以把不同 NLP 任务统一写成自然语言序列。GPT-2 更进一步：如果这些格式本来就散落在网页文本中，那么语言模型在预测下一个 token 时，理论上也会被迫学习这些模式。

换句话说，模型不一定需要显式看到“这是一个问答任务”的标签。只要训练语料里存在足够多类似问答、翻译、摘要、解释、补全的自然示范，预测下一个词这个目标就会把它们全部纳入学习过程。

## 二、方法：把语言建模扩展到“野生文本”

GPT-2 没有发明新的任务头，也没有为不同任务设计专用结构。它的技术路线很朴素：

```mermaid
flowchart LR
    Web["WebText 网页文本"] --> LM["自回归 Transformer LM"]
    LM --> Predict["预测下一个 token"]
    Predict --> Prompt["测试时给自然语言提示"]
    Prompt --> Output["直接生成答案"]
```

真正重要的是三件事：数据、输入表示和模型规模。

### 1. WebText：用 Reddit 链接筛网页

论文没有直接使用 Common Crawl。作者认为普通网页抓取包含大量低质量内容，噪声太高，不利于模型从文本中学习有价值的语言模式。

他们构造了一个新数据集 **WebText**：

| 项目 | 设计 |
| --- | --- |
| 来源 | Reddit 外链 |
| 筛选条件 | 链接至少获得 3 个 karma |
| 规模 | 去重和清洗后约 800 万文档、40GB 文本 |
| 时间范围 | 不包含 2017 年 12 月之后创建的链接 |
| 额外处理 | 移除 Wikipedia 文档，降低与评测集重叠的风险 |

这个设计背后的假设很简单：如果一个链接能在 Reddit 上获得正反馈，它至少更可能是有趣、有信息量或值得阅读的内容。WebText 不是完美数据集，但它代表了后来大模型数据工程的一条重要路线：**数据质量和数据多样性同样重要**。

### 2. Byte-level BPE (Byte Pair Encoding)：尽量不要让分词限制任务

GPT-2 使用改进的 **Byte-level BPE**。它介于字符级和词级之间：

- 高频片段可以合并成较长 token，保持效率。
- 稀有词、拼写变体、代码、符号和非英文字符仍然可以用 byte 表示。
- 模型可以给任意 Unicode 字符串分配概率，减少未知词问题。

这点对 zero-shot 很关键。既然模型要在各种未见过的数据集上直接评估，它就不能依赖某个任务的专用预处理，也不能因为测试集分词方式不同就崩掉。

### 3. 模型：四档自回归 Transformer

GPT-2 沿用 GPT 的自回归 Transformer 路线，目标仍然是：

```text
p(x) = p(x1) * p(x2 | x1) * ... * p(xn | x1, ..., x(n-1))
```

论文训练了四个大小不同的模型：

| 参数量 | 层数 | `d_model` |
| --- | --- | --- |
| 117M | 12 | 768 |
| 345M | 24 | 1024 |
| 762M | 36 | 1280 |
| 1542M | 48 | 1600 |

最大模型就是通常所说的 **GPT-2 1.5B**。相比 GPT-1，它不只是参数更多，还把上下文长度从 512 扩展到 1024 token，词表扩展到 50,257。

这里最值得注意的是：论文没有把“大模型”当作单纯工程堆料，而是把模型规模视为 zero-shot 迁移能否发生的关键变量。

## 三、Zero-shot 任务迁移：不微调，直接做题

GPT-2 的实验设置和传统评测有一个根本区别：**所有下游任务都不做监督微调**。

模型只在 WebText 上训练。测试时，研究者把任务写成自然语言上下文，让模型继续生成，或者用语言模型概率选择答案。

### 1. 阅读理解：CoQA 上达到 55 F1

在 CoQA 阅读理解任务中，输入是文档和问题，模型需要生成答案。GPT-2 在没有使用 CoQA 的 12.7 万多个训练样本的情况下，达到 **55 F1**，匹配或超过了 4 个 baseline 系统中的 3 个。

这个结果今天看不算高，但在 2019 年的语境下非常关键。它说明模型不是只会续写文章，还能在“文档 + 问题”的条件下生成相对合理的答案。

### 2. 语言建模：7/8 个数据集 zero-shot SOTA

GPT-2 最强的结果出现在语言建模迁移上。1.5B 模型在 8 个语言建模数据集中的 7 个达到当时的 zero-shot SOTA。

这个结果有两层含义：

- WebText 训练出的语言模型可以跨域迁移到新闻、百科、书籍、儿童故事等不同文本分布。
- 模型没有在这些数据集上训练或微调，说明它学到的不是某个单一语料的表面模式。

论文也强调，所有模型仍然 **underfit WebText**。也就是说，模型容量和训练还没有把训练数据吃透。这为后来的 scaling 叙事提供了早期证据：继续扩大模型和计算，很可能还能带来收益。

### 3. 翻译：英语中心语料里长出弱翻译能力

WebText 几乎全是英文，但并不完全没有外语片段。网页里常见引用、双语解释、歌词、新闻转述和翻译说明。

GPT-2 在英法翻译上表现不对称：

- 英译法较弱，WMT-14 English-French 上只有约 5 BLEU。
- 法译英明显更好，因为模型的英文生成能力很强。

这不是一个成熟翻译系统，但它验证了一个重要现象：即使没有专门构造平行语料，语言模型也可能从自然文本中的双语片段里学到可迁移能力。

### 4. 问答：事实知识来自语言建模

论文还在 Natural Questions 上测试事实问答。模型直接根据问题生成答案，例如“谁写了《物种起源》？”这类问题。

这类实验展示了语言模型的另一个特征：它会把训练语料中的事实性关联压缩进参数里。它不是查询数据库，而是在生成时调用参数中学到的统计规律。

这也埋下了后续大模型的一条主线：语言模型既像压缩器，又像知识检索器，但它的知识并不可靠，可能过时、混淆或幻觉。

### 5. 摘要：能做，但距离实用很远

GPT-2 也被测试在 CNN/Daily Mail 摘要任务上。结果说明它能生成摘要风格文本，但 ROUGE 分数并不强。

这提醒我们不要把 GPT-2 神化。它证明的是“zero-shot 能力开始出现”，不是“zero-shot 已经解决 NLP”。在很多任务上，GPT-2 仍然明显落后于有监督系统。

## 四、规模为什么是论文的主角？

GPT-2 论文最有历史价值的图之一，是不同模型规模下各任务 zero-shot 性能的变化。作者观察到，很多任务的表现会随着模型规模扩大近似对数线性提升。

这不是后来 Kaplan 等人系统提出的 scaling laws，但它已经给出了非常清晰的早期信号：

> 如果模型足够大，语言建模损失下降不只是让文本更流畅，也会让下游任务能力一起改善。

可以把它理解成三层递进：

| 层次 | 小模型 | 大模型 |
| --- | --- | --- |
| 表面语言 | 会局部续写 | 能生成长段连贯文本 |
| 任务格式 | 容易忽略提示 | 能识别 Q&A、翻译、摘要等格式 |
| 知识迁移 | 记住零散共现 | 更稳定地调用事实和模式 |

论文中的最大模型仍未过拟合 WebText，这个结论尤其重要。它意味着瓶颈不是“数据已经太少，大模型只会记忆”，而更像是“模型和计算还不够，尚未充分利用数据”。

这正是 GPT-3 的直接前奏。

## 五、为什么说这是范式转移？

GPT-2 论文的标题没有叫“大型 Transformer 语言模型”，而是叫 **Language Models are Unsupervised Multitask Learners**。这个标题其实就是它的主张。

### 1. 从“预训练 + 微调”走向“提示 + 生成”

BERT 和 GPT-1 代表的是预训练再微调：先在大语料上学表示，再针对任务训练。

GPT-2 则强调另一个方向：下游任务可以用自然语言提示表达，模型不需要改结构，也不需要更新参数。

这直接通向 GPT-3 的 in-context learning：

- zero-shot：只给任务说明。
- one-shot：给一个示例。
- few-shot：给几个示例。

GPT-3 做得更系统、更大规模，但思想源头已经在 GPT-2 论文中出现。

### 2. 为 instruction tuning 提供了基础直觉

GPT-2 认为，自然语言里已经有任务示范，语言模型会隐式学习它们。后来的 T5、FLAN、Super-NaturalInstructions 等工作，则把这件事显式化：把任务统一成 text-to-text 或指令格式，再用大量指令数据训练模型。

所以 GPT-2 和 instruction tuning 的关系可以这样理解：

- GPT-2：模型可以从自然文本中隐式学会任务格式。
- 指令微调：我们可以显式整理任务格式，让模型更稳定地遵循指令。

前者证明方向可行，后者把能力工程化。

### 3. 推动高质量网页数据成为核心资产

WebText 的 Reddit 链接筛选看起来很简单，但它影响了后来一整套数据构建思路。

后续大模型训练普遍不再满足于“抓更多网页”，而是会考虑：

- 网页质量过滤。
- 去重。
- 文档级清洗。
- 数据源配比。
- benchmark 污染检查。

GPT-2 论文还专门分析了训练集与测试集的 8-gram 重叠，发现若干语言建模测试集与 WebText 训练集有约 1-6% 重叠。这说明作者已经意识到：大规模网页训练会让“泛化”和“记忆”的边界变得复杂。

### 4. 引发开源、安全和可复现争议

GPT-2 发布时，OpenAI 最初没有立即开放 1.5B 完整模型，理由是担心大规模文本生成模型被滥用。这件事引发了社区关于安全、透明度、复现和开放研究的长期讨论。

从技术史角度看，这也很重要。GPT-2 不只改变了模型训练路线，还让大家开始认真讨论：

- 强生成模型是否应该延迟发布？
- 模型能力如何被外部审计？
- 研究开放和滥用风险如何平衡？
- 数据和模型文档应该如何写？

后来的模型卡片、数据文档、红队评估和分阶段发布，都能看到这场讨论的影子。

## 六、局限：GPT-2 证明了方向，不代表问题已经解决

GPT-2 的结果很有开创性，但论文并没有回避局限。

### 1. Zero-shot 性能不稳定

GPT-2 在语言建模上非常强，但在摘要、翻译、问答等任务上表现差异很大。它展示的是“能力萌芽”，不是成熟任务系统。

这也是为什么后来 GPT-3、InstructGPT、ChatGPT 还需要更大规模预训练、提示设计、指令微调和人类反馈。

### 2. 任务格式依赖提示

模型不会真的收到一个结构化 API 调用。它看到的是一段文本，然后继续生成。因此任务表现很依赖提示写法、上下文格式和解码策略。

这为后来的 prompt engineering 留下空间，也暴露出语言模型接口的不稳定性。

### 3. 数据污染和记忆问题无法完全消除

WebText 移除了 Wikipedia，并做了重叠分析，但互联网规模数据很难完全避免 benchmark 污染。论文发现部分测试集与训练文本存在 n-gram 重叠，也观察到模型会在某些重复文本上表现出记忆行为。

这提醒我们：评估大模型时，不能只看分数，还要看数据来源、重叠检查和测试设计。

## 七、总结：GPT-2 真正改变了什么？

如果用一句话概括 GPT-2 论文，我会这样说：

> 它把语言模型从“生成文本的模型”推进为“用自然语言接口执行任务的通用模型雏形”。

这篇论文的重要性不在于某个单项 benchmark 分数，而在于它把几条后来成为主流的路线连接了起来：

- **Scaling**：模型越大，zero-shot 迁移越强。
- **Prompting**：任务可以写进自然语言上下文。
- **Unsupervised multitask learning**：网页文本中存在大量自然发生的任务示范。
- **Data quality**：高质量、多样化数据是通用能力的重要来源。
- **Safety discussion**：强生成模型的发布方式本身成为研究议题。

从 Transformer 到 GPT-2，变化不只是架构上的。Transformer 证明了注意力可以成为通用序列建模骨架；GPT-2 则证明了在足够大规模的数据和模型上，语言建模目标本身可能孕育出跨任务能力。

这就是为什么 GPT-2 是 GPT-3、in-context learning、instruction tuning 和后续大模型浪潮的关键前奏。
