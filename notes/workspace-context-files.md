# ~/.nanobot/workspace 上下文文件速查

适用于把 nanobot 做成“特定领域任务 bot”，而不是个人助手。

| 文件 | 用途 | 进入上下文时机 | 专用任务 bot 是否建议修改 |
| --- | --- | --- | --- |
| `AGENTS.md` | 工作区级指令：任务边界、流程约定、领域规则、工具使用偏好。 | 每次对话构建 system prompt 时读取。 | **建议重点修改。** 写清 bot 的领域、职责、禁止事项、输出格式和验收标准。 |
| `SOUL.md` | bot 的长期身份、语气和执行原则。 | 每次对话构建 system prompt 时读取；Dream 可能更新。 | **建议修改。** 去掉“个人助手”定位，改成领域角色，如“合同审查助手”“数据分析 bot”。保持短而稳定。 |
| `USER.md` | 用户画像和偏好。 | 每次对话构建 system prompt 时读取；Dream 可能更新。 | **通常少改或弱化。** 专用 bot 不应过度个性化，可只保留业务方、语言、交付偏好。 |
| `HEARTBEAT.md` | 周期任务清单。gateway 按间隔检查，有活跃任务才唤起 agent 执行并通知最近活跃渠道。 | 不随普通对话进入 system prompt；由 Heartbeat 服务周期性单独读取。 | **不需修改。** 只放需要定期巡检、汇总、提醒的领域任务；没有周期任务就不管。 |
| `TOOLS.md` | 旧版 workspace 可能存在的工具契约说明。当前版本工具契约由内部模板注入。 | 当前新 workspace 不再创建；普通上下文不读取 workspace 里的 `TOOLS.md`。 | **不建议修改。** 如需工具约束，写进 `AGENTS.md`；旧文件可保留但不要依赖。 |

## 建议写法

- `AGENTS.md`：写“这个 bot 做什么、不做什么、如何判断完成”。
- `SOUL.md`：写“它是谁、语气如何、行动原则是什么”。
- `USER.md`：只放会长期影响交付的稳定偏好。
- `HEARTBEAT.md`：只放真正需要周期执行的任务。
- `TOOLS.md`：不要作为配置入口。

## 最小改造顺序

1. 先改 `SOUL.md`，移除个人助手身份。
2. 再改 `AGENTS.md`，定义领域任务规则。
3. 精简 `USER.md`，避免无关个人画像污染判断。
4. 需要后台巡检时再写 `HEARTBEAT.md`。
