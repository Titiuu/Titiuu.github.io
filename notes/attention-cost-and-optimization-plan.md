# 技术博客计划：注意力的代价及优化

## 写作目标

撰写约 6000–9000 中文字的原理长文，面向理解 Transformer 基础、希望进一步理解推理成本的读者。以“计算了什么、搬运了什么、保存了什么”为线索，解释四类优化为什么有效，以及各自没有解决哪些成本。

标题采用《注意力的代价及优化：FlashAttention、Linear Attention、Sparse Attention 和 KV Cache Compression》。

## 正文结构

### 一、一次 Attention 前向到底做了什么

- 从 Decoder Transformer 中的位置讲起：归一化、Q/K/V 投影、位置编码、因果注意力、输出投影与残差，简述 FFN，明确后文聚焦 Attention。
- 给出注意力公式、张量维度和流程图，按朴素实现说明权重与激活读取、QKᵀ、Mask/Softmax、乘 V、输出及 KV 写入；区分逻辑计算顺序与 Kernel 实际执行。
- 对比 Prefill 和单 token Decode：平方增长的注意力计算、朴素实现的平方中间矩阵、线性增长的 KV Cache，以及 Decode 对历史 KV 的反复读取。
- 给出 KV 容量公式与一组明确标注参数的 MHA/GQA 算例，区分显存容量、访存流量与 FLOPs。瓶颈结论限定于 batch、长度和硬件条件。

### 二、计算实现优化：尽量少搬中间结果

- FlashAttention：分块、片上复用、在线 Softmax，说明保持标准注意力计算语义，但浮点结果不保证逐位一致，计算复杂度仍为平方。
- FlashDecoding：沿历史序列拆分工作，再归并局部结果，改善长上下文 Decode 的并行度。
- PagedAttention：分页管理 KV，减少碎片、支持共享；明确它主要优化缓存管理，不改变注意力公式，也不直接压缩每个 KV 的表示。

### 三、KV Cache Compression：让历史状态占得更少

- 以广义“减少 KV 存储”为统一定义。
- 重点解释 MQA/GQA 的 KV 头共享，以及 MLA 的低维 latent 缓存、位置编码处理与计算路径；避免把 MLA 简化成推理时对现成 KV 做低秩分解。
- 补充 KV 量化与 token 选择/淘汰，采用 KIVI、H₂O、SnapKV 等经原始资料核验的代表方法。
- 区分训练得到的架构与推理时策略，说明精度、额外计算及信息损失；提示 token 淘汰与稀疏注意力存在交叉。

### 四、Linear Attention：用有限状态替代逐 token 历史读取

- 从可结合的特征映射形式推导递归状态，说明它通常不与原始 Softmax Attention 等价。
- 沿 Linear Attention → GLA → Gated DeltaNet → KDA 展开，解释门控遗忘、Delta 更新和更细粒度门控分别解决什么问题。
- 区分线性总计算量、固定维度的递归状态与训练/Prefill 的分块并行实现。
- 说明有限状态的容量限制，以及混合模型中保留 Full Attention 层后仍有相应缓存与计算开销。

### 五、Sparse Attention：只访问部分历史

- 从固定局部窗口 SWA，过渡到 NSA 的压缩、选择和局部分支，以及 DSA 的索引与细粒度选择。
- 介绍 CSA 的压缩后选择机制，必要时用 HCA 作简短对照；将 HISA 放在索引加速小节。
- 区分稀疏主注意力成本、索引与 Top-k 成本、缓存容量和非连续访存开销。尤其说明：选择少量 KV 不代表可以删除其余 KV，也不保证整个算法已经线性化。

### 六、组合使用与结尾

- 用对照表汇总四类的优化对象、主要节省项、语义变化、训练要求与局限；用经核验的开源模型实例说明组合方式。
- 最后用两三句话提及 Mamba 等非 Transformer 路线通过状态递推避开全注意力。将“缝缝补补”作为评价呈现，并限定其适用范围，避免把线性注意力都描述成 Full Attention 的等价改写。
